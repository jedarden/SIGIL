# bf-24w30 — Homebrew formula for SIGIL

**Task:** plan.md Phase 10 checklist marks "package managers (Homebrew formula,
AUR package)" as done, but no formula file existed. This adds one.

## What shipped

- `Formula/sigil.rb` — a Homebrew formula that builds SIGIL from the released
  source tarball and installs the full binary set
  (`sigil`, `sigild`, `sigil-shell`, `sigil-tui`, `sigil-mcp`, `sigil-proxy`,
  `sigil-ssh-agent`, `git-credential-sigil`, `docker-credential-sigil`).
- `README.md` — new **Homebrew (macOS & Linuxbrew)** subsection under
  Installation.

Install today:

```bash
brew tap jedarden/sigil https://github.com/jedarden/SIGIL
brew install sigil
```

## Why source-build instead of release binaries

This task was scoped as "installs from the GitHub Release binaries," but that is
blocked by open P0 bead **bf-37jk** (`sigil-ci` pipeline stuck — v0.5.0 was never
released; only `v0.4.0` exists). Verified 2026-07-20 via the GitHub releases API:

- Latest release: `v0.4.0` (workspace `Cargo.toml` is `0.5.0`).
- `v0.4.0` assets are **only** bare binaries `sigil` and `sigild` — **no**
  per-platform tarballs, no bottles, no versioned/archive names.
- `v0.5.0` and the full 10-binary set do not exist yet (tracked in bf-37jk /
  bf-1dkhz).

A binary formula needs stable per-platform archives with checksums. None exist,
so a binary formula today would either 404 (per-arch tarballs) or be a
non-idiomatic two-raw-binary formula pinned to an old tag covering only 2 of 10
binaries. A **source-build** formula is the robust, idiomatic, cross-platform
install that works regardless of the release-pipeline state and installs the
full toolset. That is what shipped. Source archive sha256 (v0.4.0):
`27e916d32a2ef33d369617c25feeea78176be6797d47bfe6c4cec8bcad3da846`.

## Binary formula — drop-in for when bf-37jk lands

When the release publishes per-platform archives (e.g.
`sigil-aarch64-apple-darwin.tar.gz`,
`sigil-x86_64-unknown-linux-musl.tar.gz`), replace the `url`/`sha256`/`install`
block with arch-specific stable blocks and drop the `rust` build dep. Template:

```ruby
on_macos do
  on_arm do
    url "https://github.com/jedarden/SIGIL/releases/download/v0.5.0/sigil-aarch64-apple-darwin.tar.gz"
    sha256 "<fill from release>"
  end
  on_intel do
    url "https://github.com/jedarden/SIGIL/releases/download/v0.5.0/sigil-x86_64-apple-darwin.tar.gz"
    sha256 "<fill from release>"
  end
end
on_linux do
  on_intel do
    url "https://github.com/jedarden/SIGIL/releases/download/v0.5.0/sigil-x86_64-unknown-linux-musl.tar.gz"
    sha256 "<fill from release>"
  end
  on_arm do
    url "https://github.com/jedarden/SIGIL/releases/download/v0.5.0/sigil-aarch64-unknown-linux-musl.tar.gz"
    sha256 "<fill from release>"
  end
end

def install
  bin.install "sigil"
  # ...plus sigild and any other binaries bundled in the archive
end
```

If the release instead stays as bare binaries (no archives), a minimal core
formula can pin to a tag with `resource` blocks. The v0.4.0 bare-binary sha256s,
captured for reference:

## AUR / PKGBUILD

Not shipped in this bead. An Arch `PKGBUILD` is a small additional step once
the binary-release question is settled (same asset-naming dependency). Tracked
here so a future bead can pick it up: write `PKGBUILD` against the source
tarball (mirroring this formula) or against per-arch release archives, and
document it under Installation.

## Formula mechanics notes

- `cargo build --release --locked --bins` on the workspace's virtual manifest
  compiles every member binary; `sigil-fuse` and `sigil-sdk-nodejs` are already
  in `exclude`, so no libfuse3 / napi toolchain is needed.
- `bubblewrap` is `:recommended` on Linux only (macOS has no bwrap → sandbox
  feature is unavailable there, which is a runtime concern, not a build one).
- `sigil --version` prints the crate version (`0.4.0` at this tag), so the
  `test do` block asserts against `version.to_s`.
